# 슈퍼컴퓨팅센터 중간발표 제출 패키지

2026-11-02 su-pa-fa-mu.com의 배포 소스와 공개 콘텐츠를 기반으로 만든 로컬 재현용 패키지입니다. 실제 운영 서버와 독립된 데이터베이스를 생성하며, 운영 회원·신청·문의·첨부·비밀번호·SMTP 인증정보는 포함하지 않습니다.

## 실행 준비

- Docker Desktop을 설치하고 실행합니다. Windows에서는 Linux containers/WSL 2 환경을 사용합니다.
- 처음 빌드할 때 인터넷 연결이 필요합니다. Docker 이미지, Debian 패키지, ClamAV 검사 정의를 내려받습니다.
- 여유 디스크 5GB 이상과 Docker 메모리 4GB 이상을 권장합니다. 문서 변환 실행 파일은 Linux x86-64용입니다. Apple Silicon에서는 amd64 에뮬레이션을 사용하므로 느릴 수 있습니다.
- 압축을 완전히 해제한 뒤 실행합니다. 이미 실행 중인 서비스가 8080·8025 포트를 쓰면 시작 전에 `.env`의 포트를 변경합니다.

## Windows에서 시작

1. `start.cmd`를 실행합니다.
2. 새 관리자 아이디와 15자 이상의 비밀번호를 입력합니다. 이 값은 처음 설치할 때만 사용합니다.
3. 빌드가 끝나면 사이트가 준비될 때까지 기다립니다. 첫 실행은 다운로드 속도에 따라 수 분 이상 걸릴 수 있습니다.
4. 다음 주소로 접속합니다.

| 용도 | 기본 주소 |
|---|---|
| 사이트 | http://localhost:8080 |
| 관리자 | http://localhost:8080/wp-admin/ |
| 테스트 메일함 | http://localhost:8025 |

설정만 먼저 만들려면 PowerShell에서 `powershell -NoProfile -ExecutionPolicy Bypass -File setup.ps1`을 실행합니다. 설정 파일은 로컬에 생성되며 제출 압축파일에는 실제 `.env`가 들어 있지 않습니다.

## macOS·Linux 또는 수동 실행

`.env.example`을 `.env`로 복사한 뒤 관리자와 두 데이터베이스 비밀번호를 새 값으로 바꿉니다. 관리자 비밀번호는 15자 이상이어야 합니다. `$` 등 특수문자가 있으면 dotenv의 작은따옴표로 값을 감싸세요.

```sh
cp .env.example .env
# 편집기로 .env의 REPLACE 값을 모두 변경
docker compose up -d --build
docker compose ps
docker compose logs --tail=80 web
```

`web`이 healthy이고 로그에 `Local portal initialized with a new administrator.`가 있으면 초기 설치가 완료된 것입니다. 재시작 때에는 기존 데이터와 계정을 유지합니다. `.env`의 관리자 비밀번호를 바꾸는 것만으로 기존 계정 비밀번호가 변경되지는 않습니다. 관리자 화면에서 변경하세요.

## 기본 시연 순서

1. 메인에서 센터소개, 공지, 알림판, 일정을 확인합니다.
2. 관리자 화면에 새 계정으로 로그인합니다. 신청 양식, 신청 관리, 운영 점검 메뉴를 확인합니다.
3. 별도 브라우저 또는 시크릿 창에서 일반 회원가입을 진행합니다. `student@example.test`처럼 테스트 주소를 사용할 수 있습니다.
4. 테스트 메일함에서 인증 메일을 열고 링크를 눌러 가입을 완료합니다. 외부 이메일로 발송되지 않습니다.
5. 일반 회원으로 신청서를 작성하고 출력 미리보기와 HWPX·HWP·PDF 다운로드를 확인합니다. 시연 파일로 제출합니다.
6. 첨부 검사는 최대 5분 주기로 실행됩니다. 검사 정의 다운로드가 끝나지 않았거나 검사 오류가 있으면 첨부 다운로드를 차단합니다. 관리자 운영 점검에서 상태를 확인합니다.
7. 관리자 계정으로 신청 상태를 변경하고 일반 회원 화면에서 결과를 확인합니다. 선정 회원은 포럼 접근 조건을 충족합니다.
8. 관리자 신청 양식 메뉴에서 문서 편집기를 열어 HWP/HWPX 편집·초안 저장 절차를 확인합니다. 새 양식 적용은 시험 출력을 확인한 후 진행합니다.

메일함에는 이 로컬 사이트에서 보낸 모든 메일이 보입니다. 이 구성은 localhost 시연용이며 인터넷에 공개 배포하는 설정이 아닙니다.

## 포함 내용

- `site/`: WordPress 설치본, 설치된 일반 플러그인 23개와 화면 문구 MU 플러그인, 테마 5개 전체, 공개 이미지와 번역 파일. 운영 `wp-config.php`는 제외했습니다.
- `private/`: RHWP 실행 도구·호환 라이브러리·글꼴·라이선스 및 빈 신청 양식. 운영 신청 첨부·생성 문서·로그는 없습니다.
- `seed/site.json`: 페이지, 메뉴, 공개 테스트 콘텐츠, 관련 메타데이터, 선택된 사이트 설정, 신청 양식 설정. 관리자 작성자 정보는 새 관리자 계정으로 연결됩니다.
- `docker/`: 새 환경 초기화, 로컬 메일, 정기 작업과 검사 호환 코드.
- `third-party-source/`: 기존 개발 자료에 대응하는 RHWP 원본 커밋의 소스 압축본.
- `docs/`: 구성 설명, 소스 출처, 검증 결과.

일반 플러그인은 활성 18개·비활성 5개 상태를 복원합니다. 운영 계정의 라이선스 키, SMTP 계정, 외부 서비스 토큰과 백업 작업 이력은 이전하지 않습니다. 외부 계정이 필요한 Pro 서비스의 인증 상태까지 복제한 패키지는 아닙니다. 로컬 메일 기능은 별도의 제출용 MU 플러그인이 담당합니다.

## 중지·재시작·초기화

```sh
docker compose stop
docker compose start
```

컨테이너를 제거해도 데이터를 보존하려면 `docker compose down`을 사용합니다. **이 패키지에서 만든 로컬 데이터까지 모두 지우고 새 관리자 계정으로 다시 설치하려는 경우에만** 다음을 실행하세요.

```sh
docker compose down --volumes
# 필요하면 .env의 새 관리자 설정 수정
docker compose up -d --build
```

운영 사이트에는 영향을 주지 않습니다. 이 명령은 현재 패키지의 로컬 신청·계정·메일함 데이터를 없앨 수 있으므로 시연 데이터를 보존하려면 사용하지 마세요.

## 문제 해결

- 접속 불가: Docker Desktop 실행 상태와 `docker compose ps`, `docker compose logs --tail=100 web` 확인.
- 포트 충돌: 첫 설치 전에 `.env`의 `WEB_PORT` 또는 `MAIL_PORT` 변경. 설치 후 주소를 변경하려면 콘텐츠 URL 이전도 필요하므로 중간발표용으로는 데이터 초기화 후 재설치가 간단합니다.
- 문서 변환 오류: x86-64 에뮬레이션 지원, Docker 메모리, `private/runtime` 파일 누락 여부 확인.
- 검사 대기 지속: `docker compose logs web`에서 ClamAV 정의 다운로드 상태 확인. 정의 서버 접근이 제한되면 검사를 통과 처리하지 않습니다.
- 소스 수정 반영: 제출 패키지는 최초 초기화 때 소스를 데이터 볼륨에 복사합니다. `site/` 수정 후 이미지 재빌드만으로 기존 볼륨의 소스가 덮어써지지 않습니다. 데이터를 보존할 때는 변경 파일을 컨테이너에 별도 반영하고, 새 시연 환경이라면 위 초기화 절차를 사용하세요.

사이트는 시험 운영용입니다. KBoard·챗봇·FAQ·콘텐츠 편집 및 11월 2일 오류 수정을 포함합니다. 교육 수료 이력·실제 계산 서버 연동은 별도 범위입니다. 검증 범위는 `docs/검증결과.md`를 참고하세요.

## AI 기능 설정

운영 Gemini API 키는 포함하지 않습니다. 기본 실행에서는 키 없이 관련 자료 검색·안내를 확인할 수 있으며, AI 생성 답변을 시연하려면 본인의 키를 `.env`에 `GEMINI_API_KEY='키값'` 형식으로 추가하고 `docker compose up -d --force-recreate web`을 실행합니다. 질문과 선별 문단이 외부 AI 서비스에 전송되고 해당 계정의 사용량에 반영됩니다. 이번 제출 검증에서는 외부 AI 생성 호출을 하지 않았습니다.
